# ADR-0003. Адаптеры расписания и исключения для занятий

На курс выбирается один основной источник расписания: университет или ручная конфигурация. Оба источника возвращают одинаковое представление занятия. Отмены и дополнительные занятия применяются поверх результата, а правила записи используют уже итоговые занятия и не зависят от устройства сайта университета.

## Контекст

Очередь должна открываться для той группы, у которой идёт занятие, и в пределах настраиваемого окна. Курс может использовать собственное расписание или не иметь расписания вообще. Новое требование добавляет отмену занятия и дополнительный приём вне расписания университета.

Нельзя зашить расписание ОС, номер группы, дни недели и HTML сайта в обработчик кнопки записи. Изменение вёрстки внешнего сайта не должно менять правила очереди, а перенос занятия не должен удалять существующие записи и историю.

Предоставленная ссылка на парсер расписания может служить ориентиром для будущего адаптера. В этом этапе код того репозитория не скачивался и не проверялся; работоспособность подключения к сайту университета здесь не заявляется.

## Решение: один источник и общий формат

Адаптер получает идентификатор курса, нужные группы и диапазон дат; возвращает список нормализованных занятий:

```text
Meeting(
    source_key, course_id, group_id, teacher_key,
    starts_at, ends_at, timezone, local_date,
    source_kind, revision, checked_at
)
```

`starts_at` и `ends_at` являются UTC-моментами, `local_date` соответствует местной дате начала занятия. `source_key` устойчив при изменении времени исходной пары, если источник даёт такой идентификатор. Если идентификатора нет, адаптер хранит сопоставление и не выдаёт новую сущность только из-за небольшого изменения времени. Неоднозначное сопоставление требует ручной проверки, а не слияния по совпавшему ФИО преподавателя.

Три режима курса:

| Режим | Основной источник | Результат |
|---|---|---|
| `university` | `UniversityScheduleAdapter` | Занятия указанных групп и нужного предмета/преподавателя, чётность недель и диапазон семестра учитывает адаптер |
| `manual` | `ManualScheduleAdapter` | Проверенный список дат и интервалов из конфигурации курса |
| `none` | Расписания нет | Дневная сессия для группы в местном часовом поясе |

Смешивать университетский и ручной **основной** источник нельзя. Дополнительное занятие является исключением к выбранному источнику, а не вторым расписанием. Дневная сессия сохраняет ограничения допуска и явного подтверждения; отсутствие расписания не означает отсутствие правил.

Предлагаемый контракт конфигурации, ещё не добавленный в загрузчик проекта:

```yaml
queue:
  enabled: true
  timezone: Europe/Moscow
  enrollment_lead_minutes: 15
  min_priority: -1
  semester_week_anchor: '2026-08-31'
  schedule:
    source: university  # либо manual, либо none
    university:
      group_ids: ['synthetic-group']
      subject_key: synthetic-subject
      teacher_key: synthetic-teacher
    cache_ttl_minutes: 15
```

Для `manual` вместо блока `university` используется список занятий с явным уникальным ключом, группой, преподавателем, началом и окончанием. Идентификаторы в примере синтетические; это не проверенные параметры курса ОС. Конфигурация курса остаётся источником этих настроек, таблицы `courses` и `study_groups` содержат их проверенную проекцию, а не независимый второй редактор.

## Отмены и дополнительные занятия

Оперативные исключения хранятся в `schedule_overrides`. Изменение делает преподаватель через будущий административный обработчик: автор, время и ревизия обязательны. Основной источник этих исключений один: SQLite. Редактирование YAML с дублирующими оперативными исключениями не поддерживаем; если при интеграции потребуется импорт из конфигурации, у него должен быть явный одноразовый импорт с уникальными ключами и без второго источника истины.

Два вида:

1. `cancel_day(course, group, local_date)` подавляет занятия группы на этот день и новые записи в их очереди, даже если университетский источник продолжает возвращать пару.
2. `add_session(course, group, starts_at, ends_at)` создаёт дополнительное занятие на конкретный интервал; окно открывается по тем же правилам, что и у обычной пары.

Операции выполняются в порядке: получить основной список → убрать отменённые дни → добавить разрешённые дополнительные занятия → проверить интервалы и дубликаты → сохранить проекцию. Одновременные включённые `cancel_day` и `add_session` на один день для одной группы отклоняются как противоречивая настройка: преподаватель должен снять отмену либо выбрать другую дату. Отмена другой группы или курса на эту группу не действует.

Отмена означает запрет **новой** записи; уже ожидающие не удаляются. Их состояние и события остаются доступны преподавателю до конца дня по общему правилу сохранения существующих записей. Нельзя молча пересадить их в чужую группу или дату. Если отменена ещё не начавшаяся пара и никто не пришёл, записи всё равно закрываются с объяснением в истории, а не становятся автоматически неявками.

Перенос выражается отменой исходной даты и добавлением нового занятия. Записи на старую дату не получают автоматически новую дату или место. При изменении времени существующей пары в пределах даты сохраняется `session_id`, меняются границы новой записи с событием `schedule_changed`; уже ожидающие остаются. Если новое время оказалось в прошлом, запись закрывается, но история не стирается.

## Жизненный цикл окна

Для занятия с расписанием:

```text
opens_at = starts_at − enrollment_lead_minutes
new_enrollment_allowed =
    course_enabled AND session_not_cancelled AND not_closed_early
    AND opens_at <= server_now < ends_at
existing_entries_can_be_served = server_now < expires_at
expires_at = начало следующего местного календарного дня
```

Схема использует полуоткрытые интервалы: ровно в начало запись разрешена, ровно в конец уже закрыта. Явная отмена или досрочное закрытие важнее часов. Если источник даёт занятие через полночь, адаптер отклоняет его для этой первой версии с объяснением: требование «до конца дня» иначе неоднозначно. Нужно отдельно согласованное правило, а не неявное продление.

После окончания пары новых записей нет, уже ожидающих преподаватель может принять до конца дня. В конце дня активные записи закрываются как `expired`; «не явился» назначает преподаватель, время само по себе его не доказывает. Проверка истечения выполняется при старте сервиса и при обращении к очереди, поэтому не зависит от точности фонового таймера.

Без расписания сессия длится местный календарный день. Если занятие не попало в источник, преподаватель может вручную создать внештатную сессию с явной группой и интервалом. «Открыть вручную» не означает незаметно включить запись всех групп курса. Общая межгрупповая очередь является необязательной возможностью и в первую версию не включается.

Раннее предложение записаться после автотестов может вести на постоянную страницу курса. До `opens_at` она показывает следующее занятие и допуск, но не создаёт активную запись. Переименование записи «предварительным просмотром» не должно скрывать фактическое резервирование места. Раннее согласие с последующим автоматическим резервированием отдельно не принято в этом ADR и требует согласования с заказчиком.

## Несколько групп и пересекающиеся пары

`session_id` определяет занятие, `course_id + group_id` определяет принадлежность. Одно и то же время не является ключом очереди. Две разные группы могут иметь два занятия в 10:00, не смешивая студентов. Если у одной группы пересеклись два интервала одного курса, показываем оба с понятными названиями и источником; сервер всё равно допускает одну активную запись студента на курс. Приоритет не выбирает за студента другую группу.

На одного преподавателя допускается один вызванный студент сразу по всем его занятиям. Преподаватель выбирает, какую из одновременно доступных очередей обслуживать; автоматическое слияние не выполняется. Другие преподаватели могут работать одновременно. Перенос, закрытие и истечение всегда привязаны к конкретному занятию, не к глобальному флагу «очередь открыта».

## Кэш, ошибки источника и обновления

Расписание читается для ограниченного диапазона дат, а не на каждое нажатие с полным разбором сайта. Ключ кэша включает источник, курс, группу и диапазон; время проверки и ревизия сохраняются в проекции `sessions`. TTL по умолчанию 15 минут, настраивается курсом. Исключения из SQLite применяются при каждом решении о записи и не ждут обновления внешнего источника.

Если внешний источник недоступен, свежий проверенный кэш может использоваться до истечения TTL. После этого новая запись по университетскому расписанию блокируется с понятной причиной. Старые очереди, вызов уже записанного студента и история продолжают работать. Преподаватель может явно открыть ручную внештатную сессию. Не подменяем отсутствие ответа сервера пустым расписанием и не удаляем занятия из-за сетевой ошибки.

Успешный пустой ответ для ранее существовавшей пары тоже обрабатывается как изменение расписания с сохранением записей, а не как команда удалить историю. При обновлении проверяются тип занятия, группа, предмет, диапазон семестра, отсутствие дублей и допустимые часовые пояса. Одинаковая пара из двух страниц не должна создавать две сессии.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| HTML-разбор в обработчике записи | Сбой сайта блокирует кнопку; формат внешнего сайта смешивается с правилами очереди |
| Два параллельных основных расписания | Неясно, какой источник главнее при переносе или отмене |
| Только ручное открытие | Не выполняет автоматическое открытие по расписанию |
| Только университетское расписание | Не покрывает дополнительные занятия и курсы без этого источника |
| Общий флаг открыто/закрыто на весь курс | Смешивает группы и пересекающиеся интервалы |
| Удалить очередь при переносе | Теряется история и нарушается сохранение существующих записей |

Добавление ещё одного университета должно затронуть адаптер и регистрацию источника, но не сервис очереди, схему её попыток или обработчик результатов защиты. Храним нормализованные UTC-интервалы и местную дату, а не внутренние поля HTML конкретного сайта.

## Цена решения и проверка

Добавляются нормализация занятий, кэш и обработка исключений. Это цена поддержки переноса без переделки очереди; отдельный планировщик задач и внешняя БД не требуются. Адаптер университета остаётся наиболее нестабильной границей, его надо проверять сохранёнными публичными HTML-фикстурами и отдельным интеграционным запуском при доступном источнике.

Критерии будущих тестов: обычная и чётная/нечётная неделя; отсутствие пары; открытие за указанное число минут; точные границы начала и конца; закрытие до конца дня; отмена поверх университетской пары; дополнительная пара вне основного списка; конфликт отмены и добавления; два занятия в один день; две группы в одно время; один преподаватель с двумя очередями; смена времени после записи; сохранение записей при переносе; свежий и просроченный кэш; сетевой сбой; успешный пустой ответ; повторный импорт одного источника; перезапуск после окончания дня; дневной режим без расписания.

Сейчас подготовлены проект решения и схема хранения. Сетевой парсер, расписание реального курса и перечисленные сценарии API пока не реализованы и не проверены.
