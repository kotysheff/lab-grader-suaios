# Архитектурные решения очереди

Решения команды от 06.11.2026. Документы описывают выбранную архитектуру и правила будущей реализации. Они не подтверждают согласие заказчика с отличающейся от обычной записи политикой и не означают, что очередь уже подключена к приложению.

| ADR | Решение | Основание | Статус |
|---|---|---|---|
| [0001. Приоритет с нижней границей −1](0001-priority-policy.md) | Отдельный класс просроченных работ, стабильный порядок внутри класса, повторные записи в конец | [Вычислительное исследование](../../research/queue-study/README.md) и выбор команды | Выбрано командой; уступка по основному KPI зафиксирована |
| [0002. SQLite и история](0002-sqlite-storage.md) | Локальная БД, транзакции, ограничения и журнал событий | Сравнение памяти, JSON, Sheets и внешней СУБД; [исполняемая схема](../queue/schema.sql) | Принято командой; проверена схема, интеграция впереди |
| [0003. Источники расписания и исключения](0003-schedule-adapters.md) | Один основной источник на курс; отмены и дополнительные занятия поверх него | Разделение источника расписания и правил окна записи | Архитектурный проект, адаптеры ещё не реализованы |

По предоставленному заданию обязательные темы ADR: хранение состояния/истории и расширяемое расписание. Поэтому представлены обе темы, а алгоритм вынесен в отдельное решение. Исходный шаблон из issue отсутствует в локальных материалах; использован формат «контекст → решение → альтернативы → последствия → проверка». Перед итоговой сдачей его можно переложить в предоставленный организатором шаблон без изменения содержания.

Дополнительно: [термины](../queue/GLOSSARY.md), [структура БД и операции](../queue/README.md), [тесты схемы](../queue/test_schema.py).

Материалы находятся в собственном репозитории команды. Это пакет для ревью; PR в репозиторий преподавателя и подтверждение приёмки в этот этап не входят.
