# Запуск очереди

## Включение

1. Установить зависимости по [DEVELOPMENT.md](../DEVELOPMENT.md). Для HTTP-тестов нужны `requirements-dev.txt`, для фронтенда зависимости из `package-lock.json`.
2. В нужном YAML-файле курса добавить `queue` внутрь `course`:

   ```yaml
   queue:
     enabled: true
     timezone: Europe/Moscow
     semester_week_anchor: '2026-08-31'
     required_labs: ['1', '2']
     deadline_row: 1
   ```

   Ключи работ должны совпадать с `labs`. Без `required_labs` сервер использует порядок работ из конфигурации. Дедлайны он читает из первой строки над столбцами лабораторных. Если срок отсутствует по правилам работы, преподаватель выбирает «Без дедлайна» в панели.
3. Задать `QUEUE_DB_PATH` и оставить `QUEUE_WORKER_ENABLED=1`. Пользователю backend нужен доступ на запись в каталог базы, включая файлы `-wal` и `-shm`.
4. Запустить backend и frontend обычным способом. Рабочий процесс очереди запускается при старте для включённых курсов или при первом обращении к включённой очереди.
5. Войти в существующую административную панель. В карточке предмета нажать **«Очередь защит»**, либо открыть `/admin/queue`. Во вкладке **«Расписание»** назначить занятия каждой группе.

Функция не требует новых Python- или frontend-зависимостей. SQLite входит в Python. Фоновая обработка работает внутри backend, отдельный сервис не нужен. Для первой версии следует сохранить существующую схему развёртывания с одним процессом backend.

## Студент

На прежней странице регистрации лабораторной появится вкладка **«Список на занятие»**. Форма ФИО/GitHub остаётся общей для проверки и выбора посещения.

Во время проверки сервер показывает предварительную позицию. После подтверждённого допуска он сохраняет первую обязательную незащищённую работу. По умолчанию студент не включён в состав приходящих. Кнопки «Да, я приду» и «Нет, не приду» доступны до начала занятия. Возвращение на эту страницу не требует повторной проверки.

При начале пары сервер фиксирует состав и предлагает студентам следующее назначенное занятие группы. Если следующего занятия пока нет, постоянный список остаётся видимым, а выбор посещения недоступен.

## Преподаватель

Панель показывает весь состав. Зелёные строки обозначают всех вызванных студентов, жёлтая следующего. Кнопка **«Вызвать следующего»** начинает ещё одну защиту, даже если предыдущая продолжается. Для вызванного доступны **«Сдал»**, **«Не сдал»**, **«Не пришёл»**. Повторная попытка после «Не сдал» попадает в общий конец и выделяется курсивом с пунктирной границей.

Преподаватель может добавить допущенного студента в конец или убрать активную попытку. До начала пары он может закрыть запись досрочно и открыть её снова. Результаты и история сохраняются в SQLite; эти действия не пишут оценки в Google-таблицу.

Случайный режим принудительно включён, если хотя бы один обязательный срок не удалось прочитать и ручной срок не задан. После восстановления данных сервер возвращает приоритеты от −1, если преподаватель не включил случайный режим вручную. «Без дедлайна» является корректным состоянием: такие работы располагаются после работ с известными сроками, без подстановки приоритета 0.

## Расписание и другие вузы

Во вкладке расписания преподаватель выбирает предмет и группу, указывает вуз и источник. Ручные занятия дополняют импортированные.

Для ГУАП нужны числовой ID группы из ссылки `https://guap.ru/rasp/?gr=...`, точное название предмета, при необходимости вид занятия/ID преподавателя и понедельник нечётной недели. Адаптер использует структуру [предоставленного парсера](https://github.com/markpolyak/suai-schedule-parser). Он разворачивает занятия на восемь недель вперёд с учётом чередования недель. Конец семестра ограничивает этот горизонт. Автоматическое обновление выполняется раз в час; кнопка сохранения запускает его сразу.

Для другого вуза доступны ручное расписание и импорт JSON:

```json
[
  {
    "key": "stable-lesson-001",
    "starts_at": "2026-11-13T10:00:00+03:00",
    "ends_at": "2026-11-13T11:30:00+03:00",
    "teacher_key": "teacher-1"
  }
]
```

Ключ занятия должен оставаться одинаковым при повторном импорте. Перенос сохраняет `session_id` и ответы студентов. Отменённое занятие не принимает новых записей; постоянные участники остаются в очереди. Ручная правка имеет приоритет перед обновлением источника. Если преподаватель уже принимал на занятии, для нового приёма нужно создать дополнительное занятие вместо переноса истории.

Одинаковый `teacher_key` следует использовать для одного преподавателя во всех группах и вузах. SQLite не позволит вызвать ему двух студентов одновременно. Сетевой сбой расписания сохраняет уже импортированные занятия; исчезновение занятия с сайта само по себе не считается подтверждённой отменой. Преподаватель может отменить его в панели.

## После занятия и сбои

Через 10 минут после окончания backend читает таблицу: `vv` подтверждает защиту, остальные ожидающие и вызванные сохраняют свои места. Преподаватель может продолжить их приём до 00:00 по часовому поясу занятия. В полночь backend повторно читает таблицу и закрывает оставшиеся попытки с сохранением истории. Если пара заканчивается менее чем за 10 минут до полуночи, выполняется сразу ночная сверка. Задание и время следующего запуска хранятся в БД. Сбой чтения откладывает сверку на минуту, перезапуск процесса не теряет задание; ночью вызов и отметка результата блокируются независимо от задержки фоновой задачи.

При недоступности Sheets сервер показывает последний сохранённый список с уведомлением, а изменение посещения блокирует до обновления допуска. Действия преподавателя и история работают с сохранённым состоянием. Долгий сбой может задержать закрытие попыток; состояние сверки видно под историей занятия. Уже закрытые старой версией попытки при обновлении не переоткрываются.

Если сервер был выключен в момент начала, он фиксирует состав при следующем запуске по сохранённым ответам. Сохранить изменения, сделанные только в недоступной внешней таблице во время простоя, до её повторного чтения невозможно.

## Хранение и Docker

В `docker-compose.example.yaml` добавлен именованный том `queue-data:/app/data`. Образ backend создаёт каталог с владельцем `appuser`. Шаблон использует опубликованные образы исходного проекта: для работы новых функций его нужно направить на собственные собранные образы с этой веткой. Сам шаблон не развёртывает изменения.

Нельзя удалять том командой `docker compose down -v`, если очередь нужна после перезапуска. Для SQLite нужен локальный диск; сетевой файловый ресурс для WAL не подходит.

Для резервной копии работающей базы использовать SQLite Backup API, а не копировать только основной файл без WAL:

```bash
python3 - <<'PY'
import os
import sqlite3
from datetime import datetime
from pathlib import Path
source = Path(os.environ.get('QUEUE_DB_PATH', 'data/queue.sqlite3')).resolve()
if not source.exists():
    raise SystemExit('База не найдена')
target = source.with_name('queue-backup-' + datetime.now().strftime('%Y%m%d-%H%M%S-%f') + '.sqlite3')
with sqlite3.connect(source.as_uri() + '?mode=ro', uri=True) as src, sqlite3.connect(target) as dst:
    src.backup(dst)
print(target)
PY
```

Восстановление выполняется при остановленном backend. Миграции применяются автоматически; перед обновлением нужна резервная копия. Файлы БД и их копии не следует добавлять в Git.

## Проверка

Без внешних сервисов, из корня репозитория:

```bash
python3 -m unittest discover -s tests -p 'test_defense_queue*.py'
python3 docs/queue/test_schema.py
cd frontend/courses-front
npm test
```

После установки backend-зависимостей:

```bash
ADMIN_LOGIN=test ADMIN_PASSWORD=test SECRET_KEY=test GITHUB_TOKEN=dummy \
QUEUE_WORKER_ENABLED=0 pytest tests/test_queue_endpoints.py -q
```

Проверка использует временную SQLite-базу и искусственную таблицу, внешние оценки не меняет. Затем нужно выполнить обычную сборку фронтенда `npm run build` и пройти сценарий на собственной тестовой Google-таблице: проверка работы, выбор посещения, начало пары, результат, сверка и перенос занятия.

Актуальные результаты проверок, исправленные дефекты и ограничения приведены в [аудите от 07.11.2026](AUDIT-2026-11-07.md). Полный набор HTTP-тестов теперь выполняется локально на временной SQLite-базе; реальные внешние сервисы проверяются отдельно.

## Посмотреть локально без Docker и ключей

Демонстрация использует настоящие обработчики очереди, SQLite и интерфейс приложения. Скрипт подставляет искусственную Google-таблицу, создаёт текущую и следующую пары и отключает сетевые задачи. При каждом запуске он создаёт отдельный каталог в `data/queue-demo/`. Файлы курсов и основная база не меняются.

Терминал 1, из корня репозитория (окружение `.venv` уже создано; при его отсутствии сначала `uv venv --python 3.12 .venv`):

```bash
uv pip install --python .venv/bin/python -r requirements-dev.txt
.venv/bin/python scripts/run_queue_demo.py
```

Терминал 2:

```bash
cd frontend/courses-front
npm ci --legacy-peer-deps
VITE_API_BASE_URL=http://localhost:8000 npm run dev -- --host localhost --port 5173 --strictPort
```

Открыть `http://localhost:5173/admin`, войти как **demo / demo123**, затем перейти в `/admin/courses/queue-demo/queue`. Текущая пара уже началась: можно вызывать студентов и отмечать результаты. Во вкладке расписания доступны перенос будущей пары и добавление новой.

Для студента открыть `http://localhost:5173/course/queue-demo/group/DEMO-01/lab/1`, заполнить **Иванов / Иван / Иванович / demo-ivan** и выбрать вкладку «Список на занятие». На следующую пару он пока не подтвердил приход: можно нажимать Да/Нет. Повторный запуск автотестов в демо отключён; допуски уже подготовлены.

Оба терминала нужно оставить открытыми. `Ctrl+C` останавливает соответствующий процесс. `.env`, Google service account, GitHub-токен и Docker этому демозапуску не нужны. Для работы с настоящим курсом нужны настройки из начала инструкции.

Подготовка демоданных проверена unit-тестом. Сквозные API-сценарии выполняются на искусственной таблице и реальной временной SQLite-базе; они не требуют доступа к внешним сервисам.

Для настоящего курса задайте собственный `SECRET_KEY`: отсутствие значения и старый публичный ключ по умолчанию блокируют запуск. При отдельном адресе frontend настройте `FRONTEND_URL`. Демо само создаёт случайный ключ и не требует изменения `.env`.
