# Полная локальная песочница

Проверка интерфейса и логики без Docker, ключей и внешней сети. HTTP-обработчики регистрации, проверки работы, очереди и SQLite настоящие. Ответы Google Sheets, существование пользователей GitHub и результаты CI симулируются. Это не проверка доступов к настоящим сервисам.

## Запуск одной командой

Из корня репозитория, с установленными `.venv` и frontend-зависимостями:

```bash
.venv/bin/python scripts/run_queue_sandbox.py
```

Команда запускает backend на **8010** и Vite на **5180**, поэтому прежние 8000/5173 можно оставить работающими. Ctrl+C завершает запущенные этой командой процессы.

1. Открыть <http://localhost:8010/sandbox>.
2. Нажать «Войти»: логин `sandbox`, пароль `sandbox123` уже заполнены.
3. Открыть из страницы панель преподавателя и студента. Если frontend просит вход: `sandbox` / `sandbox123`.
4. В панели выбрать курс песочницы, группу `DEMO-01` и ближайшее занятие.

По умолчанию ближайшая пара через пять минут, первые три студента подтвердили участие. Для немедленной проверки нажать «Начать ближайшее занятие сейчас» на странице управления. Текущая пара при этом не должна уже идти.

Другие порты и отдельный запуск backend:

```bash
.venv/bin/python scripts/run_queue_sandbox.py --port 8011 --frontend-port 5181
.venv/bin/python scripts/run_queue_sandbox.py --backend-only
```

Во втором случае frontend запускается отдельно с `VITE_API_BASE_URL=http://localhost:8010`.

## Сценарии

| Действия | Ожидаемый результат |
|---|---|
| Выбрать строку Иванова | Только у выбранной строки доступны действия |
| «Вызвать» | Светло-жёлтая строка, «Сдал / Не сдал / Отменить вызов» |
| «Отменить вызов» | Та же строка возвращается в ожидание на прежнем месте |
| «Не сдал» | Красная строка остаётся; повторная в конце за пунктиром |
| «Отменить» в уведомлении | Повторная строка убирается, исходная снова вызвана |
| Ожидающий → «Не пришёл» | Эта строка исчезает из первого списка, студент во втором |
| Отсутствующий → «Пришёл» | Студент исчезает из второго списка и появляется в новом круге |
| Добавить уже ожидающего/вызванного | Ошибка «Нельзя добавить студента, который уже есть в очереди» |
| Добавить отсутствующего | Новая запись в хвосте независимо от прежнего ответа студента |
| «Сдал» | Зелёная строка остаётся; следующая попытка добавляется преподавателем вручную |
| Добавить после завершённой попытки | Используется следующая допущенная работа; если её нет, допускается ручной повтор уже защищённой работы текущего занятия |
| Отключить автоповтор и сохранить | «Не сдал» не создаёт повторную строку |
| Поменять время отмены на 1 или 10, сохранить | «Настройки сохранены» после успешного ответа; следующие уведомления используют этот срок |
| Закрыть уведомление крестиком | Действие остаётся выполненным |
| Дождаться исчезновения уведомления | Действие остаётся выполненным; отмена по истечении срока запрещена сервером |

Оба списка имеют самостоятельную нумерацию от 1. В первом она продолжается через разделитель. Завершённые строки являются историей попыток, поэтому один студент может встречаться несколько раз, но активная попытка у него только одна.

## Полный путь регистрации

1. На странице управления выбрать для `demo-new`, ЛР1: «Проверки выполняются».
2. Открыть страницу студента, ввести Новиков / Никита / Никитич / demo-new, нажать регистрацию и проверку. Будет сообщение об ожидании.
3. Выбрать на странице управления «Тесты провалены», повторить проверку: тестовая ячейка станет `x`, допуска не будет.
4. Выбрать «Пройдено 2/2», повторить проверку: появится допуск. За просрочку тестового дедлайна возможна отметка `v-…` — это тоже допуск.
5. До начала ближайшего занятия нажать «Да, я приду».
6. Начать занятие кнопкой управления; проверить вызов и результаты в панели.

Состояние таблицы видно на странице управления. Кнопка её обновления читает данные локального симулятора. Изменение отметки `vv` имитирует ручную запись преподавателя; «Завершить текущую пару и сверить таблицу» запускает раннюю сверку без ожидания десяти минут. Незавершённых можно продолжить принимать до конца дня по обычным правилам.

## Сброс и сохранение

Таблица, сценарии CI и выбранная база находятся в `data/queue-sandbox/state.json`, попытки и настройки — в SQLite рядом. Перезапуск сохраняет состояние. «Сбросить песочницу» создаёт новую базу и начальные данные; старые базы не удаляются. После сброса обновить страницы студента и преподавателя.

`data/` исключён из Git. Настоящие курсы, таблицы, репозитории и основная локальная база не изменяются. Песочница слушает только локальный интерфейс.

## Автоматическая проверка

```bash
.venv/bin/python scripts/run_queue_sandbox.py --check
ADMIN_LOGIN=test ADMIN_PASSWORD=test SECRET_KEY=test GITHUB_TOKEN=dummy QUEUE_WORKER_ENABLED=0 \
  .venv/bin/pytest tests/test_queue_rounds.py tests/test_queue_sandbox.py -q
```

`--check` создаёт временные данные внутри `data/`, проверяет API без сетевого сервера и удаляет временный каталог. Сквозной pytest дополнительно проверяет регистрацию, CI pending/failure/success, посещение, вызов, результат, отмену, отсутствие/возврат, дубли, настройки, сверку и сброс.
