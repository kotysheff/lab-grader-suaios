# Проверка на публичной таблице и расписании ГУАП

Этот запуск читает настоящие открытые источники без Google service account и GitHub-токена. Посещение, вызовы и результаты преподавателя он сохраняет в отдельной локальной SQLite. Регистрацию студентов, запуск проверки GitHub и запись оценок в Google Sheets профиль блокирует на сервере.

## 1. Проверить источники

Из корня репозитория:

```bash
.venv/bin/python scripts/run_queue_live.py --check
```

Скрипт проверяет публичный CSV Google Sheets, структуру заголовков, допуски, дедлайны и получение ближайших лабораторных из HTML ГУАП. Результат сохраняется в `data/queue-live/last-check.json`. В отчёте есть количества участников/работ, наличие дедлайнов и ближайшее занятие; ФИО и GitHub-логинов в нём нет. Код возврата 0 означает успешную проверку, 1 означает ошибку с объяснением.

Источники уже заданы:

- лист: `gid=1544378737`, группа `4434`;

Связь `7116 → 4434`, тип занятия и преподаватель сверены с предоставленным `suai-schedule-parser-main/schedule.json`. Его метаданные относятся к 01.09.2026. Эти сведения служат начальными фильтрами; успешное чтение живого сайта должен подтвердить `--check`. Старый JSON скрипт не подставляет при ошибке сети.

Если `deadlines_available` равно `false`, хотя бы один срок отсутствует или не разобран. Приложение включит согласованный случайный режим, пока срок не будет получен или задан вручную. Это не подтверждение работы приоритетов на реальных сроках.

## 2. Запустить backend

После успешного `--check`, в первом терминале:

```bash
.venv/bin/python scripts/run_queue_live.py
```

Оставить процесс работающим. Backend слушает `127.0.0.1:8000`. Скрипт напечатает логин `local` и случайный пароль для текущего запуска. При перезапуске пароль меняется, а локальная очередь сохраняется.

## 3. Запустить frontend

Во втором терминале, из корня репозитория:

```bash
cd frontend/courses-front
VITE_API_BASE_URL=http://localhost:8000 npm run dev -- --host localhost --port 5173 --strictPort
```

Если на 8000 или 5173 уже работает прежнее демо, остановить его через Ctrl+C в соответствующем терминале.

Открыть:

- вход преподавателя: <http://localhost:5173/admin>;
- панель: <http://localhost:5173/admin/courses/queue-live-os/queue>;
- студент: <http://localhost:5173/course/queue-live-os/group/4434/lab/1>.

На странице студента указать свои ФИО и GitHub так, как они записаны в таблице. Профиль открывает вкладку списка и отключает кнопку регистрации. Если первая обязательная работа ещё не допущена, подтвердить посещение нельзя.

Все изначальные ответы о посещении пустые: реальные студенты этим локальным экземпляром ещё не пользовались. Нажатие «Да» изменяет только локальный список. Данные не передаются экземпляру преподавателя.

## 4. Что проверить

1. В отчёте корректные столбцы лабораторных и количество участников; в интерфейсе видны соответствующие допущенные работы.
2. Ближайшая пара соответствует сайту ГУАП. Лекции не попадают в список защит.
3. «Приду / не приду» меняет только локальную очередь; при обновлении страницы и перезапуске ответ сохраняется.
4. В панели можно увидеть расписание и назначить дополнительное локальное занятие. Для проверки вызова сейчас можно создать занятие с текущим временем, не меняя расписание вуза.
5. На начавшемся локальном занятии работают несколько одновременных защит и отдельные результаты.

Тестовые результаты преподавателя относятся к локальной истории. Они могут отличаться от реальной таблицы и влияют на выбор следующей работы в этом экземпляре. Для нового чистого эксперимента вместо удаления истории запустить с другим каталогом:

```bash
.venv/bin/python scripts/run_queue_live.py --data-dir data/queue-live-second
```

Каталоги разрешены только внутри `data/`, который исключён из Git. Рабочие SQLite-файлы с данными студентов не публикуются.

## Границы этой проверки

Публичное чтение не позволяет проверить весь цикл «наши автотесты записали `v`, преподаватель записал `vv`». Изменения отметок и ночную сверку на управляемых данных следует проверить на собственной таблице с вымышленными студентами. Для закрытой собственной таблицы потребуются свои доступы, описанные в [DEVELOPMENT.md](../DEVELOPMENT.md).

CSV-экспорт может обновляться с задержкой; доступ в браузере не гарантирует, что Google разрешит скачивание CSV. Ответ HTML, отсутствие заголовков и слишком большой ответ считаются ошибкой, а не пустой таблицей. При сетевом сбое после успешного чтения действует сохранённый снимок с пометкой устаревших данных.

Источник ГУАП разворачивает недельный шаблон в ближайшие даты. Каникулы, отмены и дополнительные пары задаются [поправками курса](../COURSE_CONFIG.md#расписание-очереди-и-поправки-курса). Предоставленный парсер использован как справочник по HTML и для сравнения данных; скачанная папка не является зависимостью запуска и не переносится в репозиторий.
