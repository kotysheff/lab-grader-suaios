# Подключение API очереди

Очередь включается отдельно для курса. Существующие курсы без `queue.enabled` сохраняют прежнее поведение.

```yaml
queue:
  enabled: true
  timezone: Europe/Moscow
  semester_week_anchor: '2026-08-31'
  required_labs: ['1', '2']
  random: false
  deadline_row: 1
  deadlines:
    '1': null  # явно без дедлайна; это не ошибка чтения
    '2': '2026-11-30'
```

Настройки размещаются внутри блока `course`, рядом с `labs` и `google`. `required_labs` определяет порядок обязательных работ. При отсутствии поля используется порядок работ конфигурации. Ручные сроки имеют приоритет перед таблицей. `null` означает отсутствие срока по правилам работы; пустая или неразобранная ячейка без ручного значения означает недоступные данные и случайный режим.

Путь к постоянной базе задаётся `QUEUE_DB_PATH`; по умолчанию `data/queue.sqlite3`. Каталог должен находиться на постоянном локальном диске/томе. Миграция применяется автоматически при первом использовании очереди.

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `GET /courses/{course}/groups/{group}/queue` | Постоянный список и ближайшее ещё не начавшееся занятие |
| Тот же GET с `?session_id=...` | Конкретное занятие, включая зафиксированный состав |
| `POST /courses/{course}/groups/{group}/queue/attendance` | Изменение посещения до начала пары |
| `POST /admin/courses/{course}/groups/{group}/queue/sessions` | Создание ручного занятия, существующая административная сессия обязательна |

Посещение передаётся через существующие поля формы:

```json
{
  "surname": "Фамилия",
  "name": "Имя",
  "patronymic": "Отчество",
  "github": "github-login",
  "session_id": "lesson-identifier",
  "will_attend": true
}
```

Сервер сопоставляет ФИО и GitHub с допущенным участником группы. Идентификация остаётся такой же, как в существующей форме; подтверждённая OAuth-личность этим способом не устанавливается. Без допуска ответ запрещён. После начала пары изменение возвращает 409, список следует обновить и показать следующее занятие.

Для ручного занятия передаются `session_id`, `teacher_key`, `starts_at`, `ends_at`. Даты начала и конца должны содержать часовой пояс, например `2026-11-13T10:00:00+03:00`.

## Состояния списка

- `unconfirmed`: допуск есть, посещение не подтверждено; полупрозрачная строка.
- `attending`: студент ответил «Да»; обычная строка с позицией среди приходящих.
- `declined`: явное «Нет»; зачёркнутая строка.

`position=null` означает, что студент не включён в состав приходящих. Интерфейс показывает предварительную строку во время проверки. Параметр `preview_lab` запрашивает оценку позиции при известных сроках; он не создаёт участника и не резервирует место.

Состав начавшегося занятия сохраняется событием `roster_frozen`. Обновление допуска в таблице не удаляет строки из этого снимка. Принадлежность к группе, состояние посещения и случайные ключи хранятся в SQLite. При работе случайного режима перезагрузка страницы не перемешивает список.

## Связь с существующей проверкой

После записи результата в Google Sheets запускается синхронизация очереди. Для уже защищённых/допущенных ячеек используется чтение таблицы; повторная запись оценки не требуется. Сбой синхронизации не отменяет успешно сохранённый результат проверки. Чтение страницы очереди повторяет синхронизацию с кэшем 15 секунд на группу.

Сетевая ошибка при наличии предыдущего успешного чтения позволяет вернуть список с `stale=true`; изменение посещения на устаревших данных блокируется до восстановления чтения. Постоянный снимок чтения хранится в SQLite и доступен после перезапуска. Отложенная сверка и административные действия подключены; подробности в [инструкции](RUNBOOK.md).

## Проверка

Чистые модули, реальная временная SQLite-база и искусственная таблица проверяются unit-тестами. Синтаксис `main.py` проверен отдельно. HTTP-тесты FastAPI и чтение реальной Google-таблицы в текущем окружении не выполнены: отсутствуют backend-зависимости и тестовые учётные данные. Для полной проверки окружение поднимается по `docs/DEVELOPMENT.md` с собственной тестовой таблицей.


## Панель преподавателя

Для маршрутов ниже сервер требует существующую cookie `admin_session`.

| Метод и путь | Действие |
|---|---|
| `GET /admin/queue/sessions` | Занятия всех курсов и групп, до 500 записей |
| `GET /admin/courses/{c}/groups/{g}/queue?session_id=...` | Полный состав, попытки, текущий/следующий, статистика и последние 200 событий |
| `POST /admin/courses/{c}/groups/{g}/queue/actions` | Вызов, результат, ручной хвост, удаление, закрытие/открытие записи |
| `GET /admin/courses/{c}/queue/settings` | Настройки и список работ; с `group_id` также текущий режим и блокировка |
| `PUT /admin/courses/{c}/queue/settings` | Сохранение `random` и словаря `deadlines` |
| `PATCH /admin/courses/{c}/groups/{g}/queue/sessions/{s}` | Перенос с `starts_at`, `ends_at` либо отмена с `cancel: true` |
| `PUT /admin/courses/{c}/groups/{g}/queue/schedule` | Сохранение объекта `config` расписания группы |
| `POST /admin/courses/{c}/groups/{g}/queue/schedule/refresh` | Обновление занятий из сохранённого источника |

Тело действия:

```json
{"session_id":"lesson-identifier","action":"result","entry_id":123,"outcome":"defended"}
```

`action`: `call_next`, `result`, `add_tail` (нужен `candidate_id`), `withdraw` (нужен `entry_id`), `close_enrollment`, `open_enrollment`. Результаты: `defended`, `failed`, `no_show`. Закрытие и открытие записи работают до начала пары. Для продолжения приёма вне расписания преподаватель создаёт ручное занятие.

Запрос настроек содержит полный набор ручных переопределений сроков. Отсутствие ключа означает чтение из таблицы, `null` означает работу без срока. После сохранения эти настройки заменяют переопределения из YAML, а не дополняют их. Настройка расписания сама по себе не меняет режим и сроки.

Конфликт состояния или времени возвращает 409, неверные параметры 422, ошибка внешнего чтения 502, изменение посещения на устаревшем допуске 503. Преподаватель может управлять сохранённым составом при `stale=true`; студент не может менять посещение до восстановления чтения.

Список маршрутов относится к включённой функции `queue.enabled`; курс без неё возвращает 404 на маршрутах очереди. [Форматы расписания и запуск](RUNBOOK.md).
